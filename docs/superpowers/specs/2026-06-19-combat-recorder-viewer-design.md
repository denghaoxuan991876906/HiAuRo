# Combat Recorder 日志阅读器设计

日期：2026-06-19

## 目标

提供一个基于现有 `WebUiServer` 静态页面分发的小工具，用于读取本地 Combat Recorder `jsonl` 日志文件，并以适合排查循环逻辑的方式展示事件组数据。

这个工具不依赖宿主前后端消息交互，不从 WebSocket 获取运行时状态，也不回写宿主状态。它只做三件事：

1. 选择本地 `jsonl` 文件
2. 解析为 `eventGroupId` 事件组
3. 用“左侧时间线 + 右侧 prev/current diff”方式展示整理后的内容

## 范围

本次只覆盖 Combat Recorder 日志阅读。

包含：

- 新增独立页面，例如 `combat-recorder.html`
- 页面脚本与样式
- 主窗口 `战斗录制` 页内新增“打开日志阅读器”入口
- 页面内本地文件选择、解析、筛选、分组、差异展示

不包含：

- 宿主与页面的双向消息
- 自动扫描宿主日志目录
- 日志编辑、标注、导出
- 多文件合并、批量对比
- 时间轴编辑器级别的导入逻辑

## 核心使用路径

1. 用户在主窗口 `战斗录制` 页点击按钮打开阅读器页面
2. 页面加载后显示空状态与“选择 jsonl 文件”按钮
3. 用户选择本地 Combat Recorder 日志文件
4. 页面解析每一行 JSON，按 `eventGroupId` 聚合为事件组
5. 左侧时间线显示事件组摘要，默认按时间顺序排序
6. 用户点击一组事件，右侧显示该组 `prev/current` 的差异视图

## 页面结构

页面采用三段布局：

- 顶部工具栏
- 左侧事件时间线
- 右侧详情面板

### 顶部工具栏

包含：

- `选择 jsonl` 按钮
- `重新加载` 按钮
- `事件类型` 过滤器
- `技能名 / ActionId` 搜索框
- `只看有变化项` 开关
- `显示原始 JSON` 开关

顶部工具栏不显示宿主运行时状态，也不承担导航职能。

### 左侧事件时间线

一行表示一个 `eventGroupId`。

每行默认展示：

- 时间
- 技能名
- 事件类型
- 关键变化摘要

关键变化摘要优先显示：

- MP/HP 变化
- 黑魔量谱变化
- Buff 变化数量
- 目标 HP% 变化

示例：

`12:54:31 火4 | GCD | MP 10000 -> 6800 | AF3 유지 | target 99.2%`

交互：

- 点击切换当前事件组
- 键盘上下切换当前事件组
- 当前选中项高亮
- `GcdReadyAndAction` 与 `AbilityEffect` 使用不同的标签颜色

左侧只承担扫读职责，不显示完整字段。

### 右侧详情面板

右侧默认显示当前选中事件组的整理视图。

展示顺序：

1. 概览
2. 资源与战斗状态 diff
3. 职业量谱 diff
4. Buff diff
5. 目标 diff
6. 原始 JSON

右侧默认采取“变化优先”原则：

- 有变化的字段高亮显示
- 无变化字段默认折叠或弱化
- 原始 JSON 作为兜底信息，默认收起

## 数据组织

页面本地解析 `jsonl` 后，转换为以下视图模型：

### 原始记录

每一行 JSON 对应一个原始快照对象。

### 事件组

按 `eventGroupId` 聚合为一组，正常情况下包含：

- 一条 `prev`
- 一条 `current`

如果某些旧日志只有单条 `current`，页面仍需兼容显示。

### 时间线项

由事件组进一步派生出时间线展示模型，包含：

- `eventGroupId`
- `timestamp`
- `eventType`
- `actionId`
- `actionName`
- `summaryText`
- `hasDiff`

### 差异视图

右侧详情不直接平铺原始对象，而是计算分区后的差异：

- 标量字段差异：直接显示 `prev -> current`
- Buff 差异：拆成新增、移除、层数变化、剩余时间变化
- 黑魔量谱差异：单独抽出关键字段高亮

## 右侧详情细节

### 概览

显示：

- 技能名
- `actionId`
- `eventType`
- `source`
- `timestamp`
- `eventGroupId`

### 资源与战斗状态 diff

显示：

- HP / MP
- GCD 剩余 / GCD 时长
- 是否移动
- 是否读条
- 连击技能 ID

格式示例：

- `MP: 10000 -> 6800`
- `GCD: 0 -> 2450ms`

### 职业量谱 diff

黑魔单独显示以下字段：

- `inAstralFire`
- `astralFireStacks`
- `inUmbralIce`
- `umbralIceStacks`
- `umbralHearts`
- `astralSoulStacks`
- `polyglotStacks`
- `isParadoxActive`
- `enochianTimer`

如果未来支持其他职业，沿用同一容器扩展，不影响当前布局。

### Buff diff

分四类展示：

- 新增 Buff
- 移除 Buff
- 层数变化
- 持续时间变化

默认先展示自身 Buff，再展示目标 Buff。

### 目标 diff

显示：

- 目标名称 / ID
- 距离
- 可选中状态
- 目标 HP / HP%
- 目标 Buff 变化

### 原始 JSON

显示 `prev` 和 `current` 两个可折叠代码块。

用途：

- 排查整理逻辑是否丢字段
- 查看未进入摘要层的原始信息

## 筛选与排序

默认：

- 按时间升序排序
- 不隐藏无变化项

支持：

- 按 `eventType` 过滤
- 按技能名模糊搜索
- 按 `actionId` 精确搜索
- 切换“只看有变化项”

“有变化项”的定义：

- `prev/current` 至少存在一个关键字段变化

关键字段包括：

- 资源
- 量谱
- Buff
- 目标 HP / 目标 Buff

## 兼容性与容错

页面需兼容以下情况：

- 旧日志只含 `current`
- 某些字段缺失
- 某些 `jobGauge` 字段不存在
- 空 Buff 列表
- 非黑魔日志
- 文件中存在空行

遇到坏行时：

- 跳过该行
- 在页面顶部显示解析警告计数
- 不阻断其余日志展示

## 实现边界

实现优先复用现有 Web 静态页面组织方式：

- HTML + 原生 JS + 现有样式体系

不引入新的前端框架。

页面通过 `WebUiServer` 提供静态访问，但不接入 `WebUiBridge`。

主窗口入口只负责打开页面 URL，不负责传文件路径。

## 测试策略

本次测试分两层：

1. 纯逻辑测试
   - `jsonl` 分组
   - `prev/current` 选择
   - 时间线摘要生成
   - 差异提取

2. 手工页面验证
   - 选择本地文件
   - 左侧时间线是否可扫读
   - 右侧差异是否正确高亮
   - 旧日志兼容性

## 推荐方案结论

采用“诊断工作台”方案：

- 左侧：事件时间线，强调快速扫读
- 右侧：差异优先详情，强调单次技能深挖
- 底部不额外增加复杂区域

这是最贴合 Combat Recorder 采样模型的方案，也最适合当前黑魔循环排查场景。
